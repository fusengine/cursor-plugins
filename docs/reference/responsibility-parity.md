# Claude-to-Cursor responsibility parity

This matrix verifies that the adjacent Claude implementation was ported by responsibility, not
used only as a visual reference. `ADAPTED` means the responsibility is present with Cursor-specific
mechanics. No Claude path, event name, global setting, or runtime assumption is copied unchanged.

All 22 reviewed responsibilities are listed: 15 are `ADAPTED`, 6 are `NOT APPLICABLE` to this
Cursor installer, and one (`Home placeholder resolution`) is scope-dependent — `ADAPTED` for
global scope, `NOT APPLICABLE` for project scope. A non-applicable row records the verified
boundary and user-facing target instead of silently omitting the source responsibility.

## Cursor-specific boundary

Cursor discovers default user-global copies as individual immediate children of
`~/.cursor/plugins/local`. Explicit project mode uses a project-relative `workspaceOpen` command;
its loader returns one absolute path per declared plugin root. Hook runtime may then invoke
`@fusengine/harness`; that runtime command does not install plugins.

The adjacent Claude repository was inspected read-only. Its global `~/.claude` paths, hook event
model, and settings format are deliberately not part of this Cursor port. This installer now also
runs on Bun (`install.sh`/`install.ps1` exec into `install-hooks.ts`), but that is a parallel,
independently-adopted choice, not a copy of the adjacent repository's bootstrap.
