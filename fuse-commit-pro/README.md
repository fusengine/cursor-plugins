# fuse-commit-pro (Cursor Plugin)

Professional git commits following [Conventional Commits](https://www.conventionalcommits.org/):
smart auto-detection of the commit type, security validation (secrets/credentials blocking),
GitHub Flow branch enforcement, auto PR creation, and a post-commit CHANGELOG / version-bump flow.

Ported from the Claude Code plugin `fuse-commit-pro` v1.2.24. The plugin name is deliberately
identical across both ecosystems so cross-plugin references (`fuse-commit-pro:<skill>`) keep
resolving.

**No `hooks/` folder.** The source plugin has no `hooks/hooks.json`, so the port has none either:
absence in the source is reproduced as absence in the port, never as an empty folder (R4–R6
preamble). Consequently this plugin declares **zero hook events and zero tool matchers**, and the
per-plugin R12 / R13 tables below are empty by construction, not by omission.

`CHANGELOG.md` and `LICENSE` are ported verbatim from the source plugin (R20c). Cursor does not
discover them; they are content, and dropping them would have been a silent loss. The source
plugin's own top-level `README.md` is **not** ported alongside this file — it occupied exactly this
path, so it is replaced by this document, with its non-redundant material folded in below
(commands table, detection rules, security rules, output shape).

## Configuration

No `variables` are declared; the plugin needs no secrets. It shells out to `git` and `gh`, so both
must be on `PATH` for the commit and PR flows.

### Auto-detection rules (from the source README, folded in per R20c)

| Pattern in the staged diff | Auto-selected command |
| :-- | :-- |

### Security behaviour (folded in per R20c)

Commits are blocked when they contain `.env` files, credentials (`password=`, `secret=`,
`api_key=`) or private keys (`*.pem`, `*.key`), and warned about for debug statements
(`console.log`, `debugger`), files over 1 MB, and TODO/FIXME comments. No AI signature is ever
added: no `Co-authored-by`, no "Generated by", no automation trailer.

## Port notes (read before editing)

### Agents

- **`model: sonnet` → `model: grok-4.6`** on `commit-detector` — the uniform-model doctrine: every
  ported agent runs on `grok-4.6`, whose default effort is `medium`, written bare (`[effort=medium]`
  would be redundant). This agent is an executant, not an organ of control, so it takes no
  `[effort=high]`. `claude-opus-*` remains barred by policy.
- **`readonly: true` added to `commit-detector`.** Its source `tools:` is `Bash, Read, Grep, Glob`
  — neither `Write` nor `Edit`, and no `mcp__*` tool — which is exactly R6's condition. In Claude
  Code the agent structurally could not write; `readonly` reproduces that at runtime. It is the
  only agent in this plugin, and it qualifies.
- **`tools:` is kept in the frontmatter, unchanged**, and a `## Allowed tools` block is emitted at
  the top of the body **in addition** (R4). `tools` is a first-class repeated field of Cursor's
  internal `agent.v1.CustomSubagent` message, but nothing proves the local `.md` YAML parser
  populates it or that it is enforced at runtime — keeping both covers either outcome.
- **`color:`, `skills:` and `effort:` are kept as-is** (R7). `color` is the one key whose absence
  is *confirmed* in `agent.v1.CustomSubagent`; `skills` and `effort` were not checked against the
  binary, so their status is unknown rather than unsupported (R19). All are harmless to keep.

### Skills

All 4 satisfy Cursor's hard rule that `name:` equals the parent folder name: `commit-detection`,
`commit-optimization`, `git-flow`, `post-commit`. `post-commit/references/` (6 files) is natively
supported and was copied verbatim (R9).

Keys preserved across the skills, absent from Cursor's documented set and **not verified against
the binary**, so unknown rather than unsupported (R19): `allowed-tools` (2 skills),
`user-invocable` (1), `related-skills` (1).

`user-invocable` was **not** translated to `disable-model-invocation` (R8) — they are near
opposites, and mapping one onto the other would invert the intent.

### Commands

All 10 commands are byte-identical to the source (R10). Cursor derives `name` from the filename;
none of them declares one, and the derived identifiers are the intended ones.

**`$ARGUMENTS` is supported — confirmed in the binary, not a risk.** The substitution function
`qxo(e,t)` is applied to command file content loaded through `_cursorCommandsService.getCommand()`:
`$ARGUMENTS` becomes the raw argument text (empty string when nothing is passed) and `$1`, `$2`, …
are substituted positionally.

**The append behaviour matters here.** The caller of `qxo` reads
`hadPlaceholders ? content = result : (raw && content = content + "\n\n" + raw)`. So when a command
body contains **no** placeholder at all but the user passes arguments, Cursor silently appends them
to the end of the prompt. Nine of the ten commands use `$ARGUMENTS` and consume their arguments
normally. **`amend.md` has no placeholder** despite declaring
`argument-hint: "[new-message] | (empty to keep same message)"` — invoking `/amend some message`
under Cursor tacks the message onto the end of the prompt rather than substituting it. The command
still works (its body asks the user for the message interactively), but the mechanism differs from
Claude Code.

Two constructs in these bodies do **not** execute under Cursor. Both are documented rather than
removed, because R10 requires the command bodies to be copied verbatim:

- **`allowed-tools:` frontmatter (all 10 commands).** The strings `allowed-tools` and
  `allowedTools` have **0 occurrences** in the Cursor binary. In Claude Code this key scoped each
  command to a whitelist of `Bash(git …:*)` invocations; under Cursor it is inert prose. The
  commands are not sandboxed to those git subcommands any more — Cursor's own permission system
  governs instead.
- **`` !`command` `` inline shell pre-execution (23 occurrences across the 10 commands).** In
  Claude Code this ran `git status`, `git log -1`, `git diff --cached` etc. *before* the prompt was
  sent and inlined the output. Cursor applies only `qxo` to command content; there is no handler
  for this syntax anywhere in the binary. Under Cursor the model reads the literal backticked text
  and must run those git commands itself as its first step — the information is still obtained, one
  round-trip later, but it is no longer pre-loaded.

## Runtime paths

This plugin references **no** harness runtime state path under `.claude/…`. The single `.claude/`
occurrence in its bodies is not a state path and needs no resolution:
`skills/commit-optimization/SKILL.md` advises adding `{"includeGitInstructions": false}` to
`~/.claude/settings.json` to drop Claude Code's built-in git instructions from the system prompt.
That is a **Claude Code product setting**, meaningful only to Claude Code users; it has no Cursor
equivalent, and rewriting it to `.cursor/…` would point at a setting that does not exist. It was
kept verbatim as documentation of a Claude Code–specific optimisation. The R21 clause is
deliberately not reproduced here: it asserts that this plugin's bodies reference harness
`.claude/…` state files, which would be factually false.

## Not portable

- **`allowed-tools:` command scoping** — 0 occurrences in the Cursor binary, so the per-command
  `Bash(git …:*)` whitelists no longer restrict anything. Kept verbatim (R10) but inert.
- **`` !`command` `` pre-execution in command bodies** — no handler in the binary; the git context
  those 23 snippets pre-loaded is now fetched by the model at runtime instead.
- **`/amend` argument substitution** — no placeholder in the body, so Cursor appends the argument
  instead of substituting it (documented above, not a removal).
- No hook event or tool matcher is lost, because this plugin declares none.

## Install locally

Clone the repository and point Cursor at this plugin directory, or install the whole repository as
a marketplace via its root `.cursor-plugin/marketplace.json`. Hooks are not involved, so `npx` is
not required for this plugin.
