## Findings

- Native Cursor APEX state belongs under `.cursor/apex`.
- Harness cache state belongs under `.harness/cache`.
- Claude compatibility inputs such as `.claude/settings.json`, `.claude/skills`, and `.claude/agents` must not be globally renamed.
- Executable Claude marketplace paths and `$CLAUDE_PLUGIN_ROOT` references are invalid in native Cursor commands unless a documented compatibility path exists.
- The published harness 0.1.90 differs from the newer local source and still has Cursor runtime defects. The harness must remain read-only; required changes are delivered as a standalone prompt.
- Hook commands must not be pinned to 0.1.90. Exact pinning and blocking-hook hardening wait for a corrected harness release.
- Hook manifests are trigger/configuration surfaces (event, matcher, command, timeout, and direct
  prompt entries). The 62 command entries delegate runtime mechanics to the harness: stdin
  normalization, gates, state, response rendering, and blocking exit status `2`.

## Safe Cursor-only scope

- Correct proven state paths and stale executable instructions.
- Remove or replace references to missing plugin assets.
- Update documentation so it distinguishes native Cursor behavior from supported Claude compatibility behavior.
- Add verification that detects executable Claude-only paths without rejecting intentional compatibility references.
- Add a standalone harness correction prompt under `docs/`.
